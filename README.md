# المنصة السورية لإدارة وجدولة الري — v0.6

منصة ويب تعمل كلياً في المتصفح لحساب ET₀ وفق FAO-56 Penman–Monteith والموازنة المائية في منطقة الجذور وتنبيهات الري في سورية.
النسخة الحالية HTML/JavaScript، والانتقال إلى ASP.NET Core/Blazor مؤجَّل إلى المرحلة الأخيرة.

## ما الجديد في v0.6
1. **خريطة سورية صحيحة:** حدود المحافظات الحقيقية (geoBoundaries ADM1، CC BY 4.0) بدل المضلعات المرسومة يدوياً. الإسقاط مصحَّح بمعامل cos 34.8° حتى لا يتمدد الشكل أفقياً.
2. **حل مشكلة NASA POWER:** لم يعد المتصفح يتصل بـ NASA. يعمل GitHub Actions يومياً على خوادم خارج سورية، فينزّل بيانات شبكة سورية ويحسب ET₀ لكل خلية، ثم يحفظ النتائج في `data/nasa/`. المنصة تقرأ من هذا الأرشيف (وضع «أرشيف المنصة»).
3. **تصحيح علمي:** كانت النسخة السابقة تضرب `ALLSKY_SFC_SW_DWN` في 3.6. هذا خطأ لأن المجتمع AG يعيد الإشعاع أصلاً بوحدة MJ m⁻² day⁻¹، فكانت قيم ET₀ القادمة من NASA مضخَّمة. أصبح التحويل الآن مشروطاً بوحدة الاستجابة.
4. **تحقق من المحرك:** محرك ET₀ في المتصفح (JS) وفي الخادم (Python) يعطي 3.88 mm/day لمثال FAO-56 رقم 18، والقيمة المنشورة 3.9. ويُختبر المثال تلقائياً قبل كل مزامنة.


## التشغيل لأول مرة على GitHub
1. **Settings → Pages:** اختر Deploy from branch، ثم الفرع `main` والمجلد `/ (root)`. يظهر بعدها رابط المنصة.
2. **Actions → NASA POWER sync → Run workflow:** اترك الحقول فارغة لتنزيل آخر 20 يوماً.
3. **ملء الأرشيف التاريخي:** شغّل الـ workflow يدوياً سنة بسنة، مثلاً `start=20250101` و`end=20251231`.

## ملاحظات علمية
- الشبكة: الأرصاد بدقة MERRA-2 (0.5° × 0.625°)، والإشعاع من CERES/FLASHFlux.
- المحافظات الأصغر من خلية واحدة (دمشق، اللاذقية، طرطوس) تأخذ قيمة أقرب خلية، وهذا موسوم بـ `method: nearest-cell`.
- الإشعاع الشمسي في NASA POWER يتأخر عدة أيام، لذلك تعرض الخريطة **آخر يوم مكتمل** (أي يوم فيه 80% على الأقل من خلايا سورية لها ET₀). تنبيهات الري المستقبلية تحتاج مصدر تنبؤات جوية، وسيُضاف في مرحلة لاحقة.
- مسار الرطوبة لبيانات NASA هو `T2MDEW → ea = e°(Tdew)`، وفق المعادلة 14 في FAO-56.
